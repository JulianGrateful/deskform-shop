### 2. Структура Коллекций (Схемы данных)

В проекте используется 4 основные коллекции:

#### A. `users` (Пользователи/Дилеры)

Хранит профили дилеров.

* **_id:** `Int64` (Telegram User ID).
* **Ключевые поля:**
* `client_type`: Статус (`new`, `new_partner`, `active`, `market_urikzar` и т.д.). **Важно:** Watcher следит за изменением этого поля.
* `city`: Город доставки (используется для логистики).
* `phone`: Контактный номер.
* `full_name`, `username`.


* **Индексы (подразумеваемые):** `city` (для поиска транзитных дилеров).

#### B. `orders` (Заказы)

Хранит данные о покупках.

* **_id:** `ObjectId` (генерируется автоматически).
* **Ключевые поля:**
* `user_id`: Ссылка на `users._id`.
* `items`: Массив объектов (товары, цены, количество).
* `total_final`: Итоговая сумма к оплате.
* `status`: `new` (на проверке) -> `approved` -> `shipped` -> `rejected`.
* `shipping_method`: `standard` (Фура) или `express` (Такси).
* `delivery_type`: `standard` или `dropshipping`.
* `recipient_info`: Объект (ФИО, тел, адрес) если это Дропшиппинг.



#### C. `consolidations` (Логистика / Рейсы)

Используется для группировки заказов типа `standard` в одну фуру.

* **_id:** `ObjectId`.
* **Ключевые поля:**
* `destination`: Город назначения (например, "Самарканд").
* `status`: `open` (идет набор) или `closed` (уехала).
* `total_sum`: Сумма всех заказов в этом рейсе (для расчета % заполненности).
* `orders_count`: Количество заказов.
* `order_ids`: Массив `ObjectId` (ссылки на коллекцию `orders`).



#### D. `routes` (Маршруты)

Используется для определения транзитных городов ("Цепная реакция").

* **Структура:**
* `name`: Название маршрута (например, "Ташкент-Термез").
* `points`: Массив объектов `[{city: "Гулистан"}, {city: "Джизак"}, ...]`.


* *Примечание:* В коде (`main.py`) реализован **Fallback**: если в БД нет маршрута, используется статический словарь `RouteManager.STATIC_ROUTES`.

### 3. Ключевая логика взаимодействия с БД

#### 1. Database Watcher (Change Streams)

* **Функция:** `start_db_watcher()`
* **Логика:** Слушает коллекцию `users` на предмет событий `update`.
* **Триггер:** Если изменяется поле `client_type` (например, админ поменял статус через MongoDB Compass), бот **мгновенно** отправляет уведомление пользователю в Telegram с новой клавиатурой.

#### 2. Consolidation Logic (Атомарные операции)

* При добавлении заказа в существующий рейс используется `$inc` и `$push` для избежания гонки данных:
```python
await consolidations_collection.update_one(
    {"_id": flight['_id']},
    {
        "$inc": {"total_sum": order_sum, "orders_count": 1},
        "$push": {"order_ids": order_id}
    }
)

```



#### 3. Chain Reaction (Geo-Targeting)

* **Функция:** `trigger_chain_reaction(destination_city)`
* **Логика:**
1. Определяет список транзитных городов (через `RouteManager`).
2. Делает выборку пользователей из БД по этим городам:
```python
query = {"city": {"$in": ["Гулистан", "Джизак"]}}
cursor = users_collection.find(query)

```


3. Рассылает им уведомления.
